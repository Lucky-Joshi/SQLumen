# Support

## Where to Ask

- **Questions:** Open a
  [Question issue](https://github.com/Lucky-Joshi/SQLumen/issues/new?template=question.md)
  after checking the documentation.
- **Feature requests:** Open a
  [Feature Request](https://github.com/Lucky-Joshi/SQLumen/issues/new?template=feature_request.md).
- **Bug reports:** Open a
  [Bug Report](https://github.com/Lucky-Joshi/SQLumen/issues/new?template=bug_report.md).
- **Optimization rules:** Use the
  [Optimization Rule](https://github.com/Lucky-Joshi/SQLumen/issues/new?template=optimization-rule.md)
  template.
- **Documentation:** Open a
  [Documentation issue](https://github.com/Lucky-Joshi/SQLumen/issues/new?template=documentation.md).
- **Discussions:** Use GitHub Discussions for design conversations and
  questions that benefit from community input.
- **Security reports:** Follow [SECURITY.md](SECURITY.md); never disclose a
  vulnerability in a public issue.

## Before Asking for Help

1. Search existing issues and discussions.
2. Read the relevant document in [docs/README.md](docs/README.md).
3. Confirm the issue is reproducible with a supported dialect.
4. Remove secrets, credentials, and sensitive SQL.
5. Record the commit, version, operating system, and relevant configuration.

## Good Bug Reports

Include a minimal reproducible SQL query, dialect, expected behavior, actual
behavior, exact error messages, screenshots when useful, safe logs, and the
smallest reliable reproduction path.

## Feature Requests

Describe the user problem, proposed solution, alternatives considered, users
affected, privacy implications, and how success could be evaluated. Requests
should align with SQLUMEN's deterministic, privacy-first, educational, and
accessible design principles.

## Documentation Contributions

Documentation improvements are welcome. Link the affected document, explain
what is unclear or outdated, and propose corrected wording or examples. See
[CONTRIBUTING.md](CONTRIBUTING.md) for the review workflow.

## Response Etiquette

Maintainers and community members aim to acknowledge requests within a
reasonable time. Please remain constructive, provide requested details
promptly, and avoid posting duplicate requests or private information.
